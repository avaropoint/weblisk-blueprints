## What this covers

How software is specified, designed, written, reviewed, tested and made ready for release: the practices applied while it is being built, and the assurance gathered before it is a candidate to deploy.

## Why these requirements

A procedure, because this domain is almost entirely practice, and a practice nobody wrote down is a preference held by whoever is currently senior. A register, because the finding — from a review, a test, a scan — has to be tracked to closure or the assurance was theatre. A policy, because which of these apply to which code is a decision, and one that is otherwise made per team.

## How it goes wrong

It is claimed by an organisation that does not build software, because the phrase appeared in a standard. An excluded control stated as excluded is stronger than a permanently unanswerable one.
