# Checks

Small checks the corpus runs on itself, for rules no tool checks yet. Each one
reads its rules from the corpus file that states them and keeps no copy, and
each runs with a control: a case the check must fail, so that a check which
reaches nothing cannot pass.

```
checks/run.sh
```

runs them all and exits 0 only when every check passes and every control
fails. They need Python 3 and PyYAML, and `statements.py` and
`namespace-registry.py` need OpenSSL 3.5 or later. A check that cannot run
fails; it never passes for want of something to read, and OpenSSL's leg of the
statement vectors is no exception. The one exception is the statement vectors'
circl and noble legs ([`ml-dsa/`](ml-dsa/)), and only for want of the tool:
with no `go` on PATH, or without the pinned `@noble/post-quantum`
(`npm ci --ignore-scripts` in `checks/ml-dsa`, or `NOBLE_DIR` naming a
directory that holds it), the leg prints `NOT RUN`, never `ok`, and
`REQUIRE_ALL_VERIFIERS=1` makes it a failure. A `go` that is on PATH and cannot
build the generator — a compile error, or a module cache without circl — fails.

| Check | What it holds the corpus to | Control |
|---|---|---|
| [`ids.py`](ids.py) | Every ref in [`vectors/ids.json`](../vectors/ids.json) parses as [`schemas/names.md`](../schemas/names.md#the-grammar) says, and reads back from YAML unchanged | A parser that accepts everything is reported on every invalid vector |
| [`names.py`](names.py) | No file names a namespace that is neither reserved nor this repository's own ([`schemas/names.md`](../schemas/names.md#where-a-namespace-may-appear)), and the vectors' families are the declared ones | A fixture naming an unreserved namespace is reported, once |
| [`retired.py`](retired.py) | [`RETIRED.md`](../RETIRED.md)'s entries: one per table row, in order, naming only spellings the row names, with a closed `match` vocabulary, paths that exist, patterns that compile, and no allowance whose `until` its file has reached. `--scan` also lists every place a retired spelling remains where its entry does not allow it; it reports and does not gate | A copy missing its last entry, and a copy whose allowance has ended, are each reported |
| [`requirement-ids.py`](requirement-ids.py) | Requirement ids carried in `wl:id` comments, and the checklist items whose `wl:check` comments cover them: each id declared once in its file and every covers naming one of them; in a file marked `wl:ids complete`, every statement saying MUST carries an id and every id is covered. The corpus's migration turns both into requirement and `verifies` ids unchanged | The complete file with its last `wl:check` removed is reported, naming each id only that check covered |
| [`timestamp-wire.py`](timestamp-wire.py) | Each `languages/` and `platforms/` mapping's `timestamp` row, applied to the instant in [`vectors/timestamp-wire.json`](../vectors/timestamp-wire.json), gives the vector's wire value | `--control` rewrites `languages/go.md`'s row to milliseconds in memory and passes only if that one disagreement is reported |
| [`spans.py`](spans.py) | Every file in [`vectors/grammar/`](../vectors/grammar/README.md) has an expected projection, and each projection partitions its file: spans sorted, contiguous and covering `[0, length)`, at the file's own length and `version_hash` ([`schemas/family`](../schemas/family.md), `spans-partition`) | A copy whose projection leaves a one-byte gap is reported, once; a copy with a vector and no projection is reported; a directory with no vectors is reported |
| [`findings.py`](findings.py) | Every finding code [`schemas/family`](../schemas/family.md#definitions) declares has exactly one policy, fixed by its `finding` definition or left to the declaration, and every vector's findings carry that policy, in order of span start, then code, then subject (`findings-closed`); a declaration with CRLF line ends reads the same | A copy whose multi-root finding is only reported is reported, once; a copy whose missing-key finding is refused is reported, once; a copy of `family.md` that gives `multi-root` no policy is reported |
| [`refs.py`](refs.py) | Every `$ref` in a family declaration is `#/$defs/<name>` or `<ref>#/$defs/<name>` and resolves to an entry of that declaration's `defs` block ([`schemas/family`](../schemas/family.md), `schema-refs-resolve`) | A copy of the test declaration citing `blocks#/$defs/`, which names no file, is reported once per ref |
| [`reach-depth.py`](reach-depth.py) | The fabric's reach depth is stated as data in exactly one place, requirement `reach-max-depth` in [`architecture/fabric.md`](../architecture/fabric.md#requirements) (D23), `architecture/change-management.md` cites it, and every citation of a fabric requirement, `fabric.md`'s own included, names one that exists. A depth key counts only where it or an enclosing key names a walk, so a queue's or a nesting depth is not this number | A copy of `architecture/` whose change-management states `depth_limit: 10` again is reported with exactly two places; a copy adding a queue and a nesting depth still passes; a copy adding a traversal `max_depth` is reported; a copy of `fabric.md` citing a misspelt requirement of its own is reported |
| [`fabric-ledger.py`](fabric-ledger.py) | [`vectors/fabric-ledger.json`](../vectors/fabric-ledger.json) chains as [`architecture/fabric.md`](../architecture/fabric.md#the-ledger) says, checked with SHA-256 and an RFC 8785 canonicaliser alone: each entry's canonical line has the recorded digest, `seq` runs from 1, and each `previous_digest` follows. Each claim's relation is one [`schemas/kinds.md`](../schemas/kinds.md#relations) declares between its kinds, and an end whose kind is not versioned cites a projection. Every field a `cited_version` carries is one `architecture/fabric.md` binds `ContentIdentity` with, so a fabric generated from that binding reads the `projection` it compares on | A copy whose third entry is altered is reported with exactly one fault, at that entry; a copy whose provider end cites a bare version, and one relating code to a mapping rule by an undeclared relation, are each reported at that entry; a copy of `fabric.md` bound without `projection` is reported with exactly that field. `--relation` answers for one relation, so the table's multi-relation rows, its `any content kind` and its `the same kind` are each read as written: `copied_from` from policy to policy is declared, and to procedure is not |
| [`digest-spelling.py`](digest-spelling.py) | Every blueprint sentence describing a SHA-256 as hex without the `sha256:` prefix is in a file [`patterns/content-identity.md`](../patterns/content-identity.md)'s digest-spelling rule names as a gap, and every file the rule names still writes one, so the list grows with a new bare-hex field and shrinks when a blueprint adopts the spelling. A key fingerprint keeps its own form and is not counted | A copy whose rule forgets `protocol/types` is reported with exactly that file |
| [`type-refs.py`](type-refs.py) | Every full type ref in the `weblisk` namespace, `type://weblisk/<file>:<Name>`, names a type its file declares under a `types:` key ([`schemas/names.md`](../schemas/names.md#families)) | A copy whose run statement misspells its build type is reported with exactly that ref |
| [`statements.py`](statements.py), [`ml-dsa/`](ml-dsa/) | Every vector in [`vectors/fixed-form-statements.json`](../vectors/fixed-form-statements.json) verifies with three ML-DSA implementations outside every Weblisk tool — OpenSSL (`statements.py`), circl (`ml-dsa/main.go`) and `@noble/post-quantum` (`ml-dsa/noble.mjs`): each key's seed, fingerprint and public key agree, each message is its prefix and fields joined by 0x00, and each signature verifies. Every prefix [`protocol/identity`](../protocol/identity.md#fixed-form-statements) registers has vectors or is named there as having none yet, and its list of prefixes with vectors is exactly those that have them. `ml-dsa/main.go` is also what makes the vectors (`go run . gen`): it writes `fixed-form-statements.json` and every signature in [`vectors/namespace-registry.json`](../vectors/namespace-registry.json), and its check requires a rerun to write both byte for byte; circl and noble also verify every registry signature | In each of the three, `--flip` changes one byte of one vector's message, and exactly that vector is reported; `--flip all` changes every vector's, and every one is reported. A copy of the vectors without the namespace statements is reported by circl as not what `gen` writes
| [`namespace-registry.py`](namespace-registry.py) | Every step of [`vectors/namespace-registry.json`](../vectors/namespace-registry.json) gets the verdict [`patterns/namespace`](../patterns/namespace.md#deciding-a-statement) gives it, and every sequence leaves its stated state; the four statements the pattern defines are registered and have vectors; no fixed route segment sits where `{namespace}` does with a word someone could claim | A registry that accepts confusable names, one that accepts a one-sided transfer, and a verifier that holds no release to the one before it, are each reported at exactly the steps the vectors refuse for that reason; one that lets a retired name be claimed again, one whose rotation drops the grants, and a verifier that judges a release at the registry's tip rather than its `released_at`, are each reported only in the sequences that exercise the rule, at its first bite; a copy of the pattern serving its log at `/v1/namespaces/log` is reported with exactly that route |

A check here is temporary by design: when a tool implements the rule, the
check moves there and leaves this directory.
